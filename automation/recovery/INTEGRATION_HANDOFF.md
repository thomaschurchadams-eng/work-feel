# Reliability Watch integration boundary

The existing `scripts/run-secure-operations.cjs` executes in an ephemeral GitHub Actions job on `main`. Its run 38257568883 receipt stopped at the three-minute production identity wait for eb075a6 with zero side effects. The later READY deployment is external evidence, but the failed job cannot resume after exit. The repository's local file adapter cannot persist a lease or checkpoint across separate hosted Actions workers.

The existing operations runner now emits a sanitized `recovery` handoff in its uploaded run receipt on failure: run/SHA operation ID, an explicit unresolved bus key, failed stage, pre-invocation action-start state and acknowledgment counters. Its legacy `incidentKey` field is an operation correlation ID, **not** the issue-bus `dedupeKey`. Zero acknowledgments must never be read as proof of zero external side effects. This is the repository-side integration point. The current `reliability-watch` owner is an externally managed Cloud task, coordinated through issue #160. This repository does not contain that task's executable prompt, state store or issue-writing credentials. Wiring this helper into `run-secure-operations.cjs` would put incident closure under a different actor and would still lose its checkpoint when the job ends. No active task, schedule or production workflow is changed by this PR.

To activate the reviewed behavior within the existing owner, Reliability Watch must map the run/SHA operation ID to the issue-bus key from the original blocker event before acquiring a checkpoint or closing anything. `issue-bus-closure.cjs` checks the blocker event's exact run/SHA evidence and a completion event that cites the blocker, run and SHA. It returns `isClosed(busKey)` through fresh issue reads. The owner needs a shared transactional checkpoint store with atomic per-bus-key lease/CAS and an idempotent same-key close for issue #160. The owner should ingest the failed run receipt and exact deployment SHA, reconcile every prior side effect, then invoke `recover` with only the unfinished authorized steps. Map permission denials to `PERMISSION_DENIED`, transport-unknown writes to `AMBIGUOUS_OUTCOME`, and verify exact production and persisted result before close. Keep the actual bus key and existing approval boundaries. The file adapter and isolated integration fixtures show the contract; they are not suitable as cross-worker Cloud state.

Activation requires a separately reviewable update to that externally managed task and its durable store. Until then, this draft provides a tested implementation contract and a handoff, not automatic recovery.
